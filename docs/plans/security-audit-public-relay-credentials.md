# 公开线路与中继落地凭据安全整改 TODO（2026-09-08）

## 目标与背景

本规划承接 2026-09-08 对当前 Git 工作区执行的标准 Codex Security 全仓库静态扫描，专门整改两条高可信凭据问题。规划只记录待实施工作，不代表问题已经修复；所有任务完成前不得归档。

审计基线：

- **高危：固定测速凭据进入公开线路入站。** `apps/server/src/common/constants.ts:35-38` 定义固定测速 UUID/Secret，`apps/server/src/agent-gateway/agent-gateway.service.ts:1070-1087` 在订阅权益过滤后无条件追加测速用户，随后由公开线路入站生成逻辑接受；协议凭据映射见 `apps/server/src/common/inbound.ts:857-927`。
- **中危：固定中继凭据进入协议代理落地入站。** `apps/server/src/common/constants.ts:30-33` 定义固定中继 UUID/Secret，`apps/server/src/agent-gateway/agent-gateway.service.ts:1180-1192` 将其放入 `PROTOCOL_PROXY` 落地端口入站，同时 `:1281-1320` 的中继出站复用同一凭据。
- 默认监听地址为 `0.0.0.0`（`apps/server/src/common/ports.ts:3`），部署防火墙不能替代应用层凭据隔离与轮换控制。
- 扫描未发现需要立即改动的普通用户 IDOR、Master-Agent 鉴权绕过、SSRF、路径穿越或 Go Agent 命令注入问题；本规划不扩大到这些已判定为无问题的区域。

## 修复原则与终态

1. **源码不再包含可直接认证的固定 UUID、密码或用户名。** 禁止用“换一个固定字符串”作为修复。
2. **公开线路只接受真实订阅权益用户。** 测速身份不得继续作为普通用户追加到公开 Sing-box 入站。
3. **测速能力与公开代理认证解耦。** 优先让 Agent 在节点本地或受控的 Master-Agent 通道内执行探针；若过渡期仍需远程入站，必须是短时、按线路生成、可立即撤销的临时凭据，并明确记录过渡风险。
4. **中继凭据按线路/中继实例隔离。** 入口出站与落地入站只共享对应线路的凭据，不得跨线路、跨节点或全局复用。
5. **凭据必须可轮换、可失效、不可进入日志、订阅、URL、前端响应和错误信息。** 持久化时复用现有 AES-GCM 密钥体系，不新增外部数据库、Redis、消息队列或运行时依赖。
6. **配置切换必须成对生效。** 中继入口与落地端任一侧未完成新凭据下发时，不得继续宣称线路可用，避免新旧凭据错配造成明文回退或绕过。

## 不在本规划范围内

- 不重做订阅格式、用户套餐权限模型或整体 Agent WS 协议；只有当测速迁移确实需要新增受控任务时，才扩展现有消息协议。
- 不把公网防火墙、云安全组或人工运维步骤当作唯一修复；部署限制只能作为纵深防御。
- 不引入新的外部存储或密钥服务；如现有加密存储无法满足按线路凭据生命周期，先补 RFC 和数据模型设计，再实施迁移。

## 里程碑与任务清单

### 里程碑 0：复现、设计冻结与兼容边界

- [ ] 0.1 将两条扫描发现转成服务端失败用例：构造无订阅用户的公开直连线路，证明当前配置仍生成测速用户；构造 `PROTOCOL_PROXY`，证明落地入站与入口出站使用相同固定中继凭据。
- [ ] 0.2 盘点测速调用链：确认 `LineSpeedtestService` 的执行位置、Master 本地 Sing-box 能力、Agent 可执行的现有任务类型，以及直连线路、盲转发、协议代理和目标线路桥接的测速行为。
- [ ] 0.3 盘点线路与节点字段，确认是否已有可用的内网地址、监听地址、Agent 任务回执和配置版本号；明确中继落地端的可达网络边界，不假设所有 VPS 都有私网互联。
- [ ] 0.4 冻结凭据策略：测速采用“Agent 本地探针/受控任务”为目标终态；中继采用“每条中继线路独立凭据 + 现有 AES-GCM 加密持久化或等价受保护方案”。若必须新增 Prisma 模型，先列出迁移、回滚和数据模型文档影响。
- [ ] 0.5 写明过渡期策略：不得保留固定凭据兼容分支；若需要新旧配置短暂共存，旧凭据必须仅在受限维护窗口内存在，并由明确的失效时间、审计日志和回滚步骤约束。

### 里程碑 1：建立受保护的线路凭据服务

- [ ] 1.1 新增统一的 `LineCredentialService`（命名以现有模块风格为准），集中负责生成、读取、轮换、撤销和脱敏，不在 `AgentGatewayService`、测速服务和控制器内各自实现凭据逻辑。
- [ ] 1.2 使用现有 CSPRNG 和 AES-GCM 加密能力生成凭据；UUID、密码和协议用户名按协议要求生成，密码至少使用足够长度的随机字节编码，禁止可预测的线路 ID、时间戳或固定前缀作为唯一秘密。
- [ ] 1.3 为凭据定义用途和作用域：至少区分 `RELAY_TRANSIT` 与过渡期 `SPEEDTEST`；作用域必须包含线路 ID，必要时包含入口/落地节点 ID，禁止用单个全局凭据覆盖所有线路。
- [ ] 1.4 确定持久化实现并完成数据模型设计：优先增加明确的线路凭据模型/字段，保存密文、用途、版本、创建时间、撤销时间和必要的哈希索引；禁止把明文凭据写入普通配置 JSON、日志或迁移脚本。若复用已有加密字段，补充字段用途和生命周期说明。
- [ ] 1.5 为读取和轮换增加并发控制，确保同一线路不会因并发配置构建生成两套有效凭据；凭据读取失败时安全失败，不回退到旧的源码常量或默认密码。
- [ ] 1.6 增加敏感值脱敏测试，覆盖异常、日志、配置下发回执、管理员 API、节点详情、订阅输出和前端序列化路径。

### 里程碑 2：移除公开线路中的测速凭据

- [ ] 2.1 删除 `INTERNAL_SPEEDTEST_EMAIL`、`INTERNAL_SPEEDTEST_UUID`、`INTERNAL_SPEEDTEST_SECRET` 等可认证的源码常量，以及 `internalSpeedtestUser()` 的全局静态实现。
- [ ] 2.2 修改 `usersForLine()`：公开线路用户列表只由已通过套餐/额外线路授权的真实用户组成；补充测试证明空订阅线路不会因为系统用户而变成可认证代理入口。
- [ ] 2.3 设计并实现 Agent 本地测速路径：由 Master 下发明确的探针任务或复用现有受控任务，让 Agent 在节点本地访问对应 Sing-box 入站/出站；探针结果必须绑定节点、线路和任务 ID，并设置超时、取消和最大执行时长。
- [ ] 2.4 对中继线路定义测速起点和路径：直连线路从入口节点探测；协议代理从入口节点探测完整转发链路；落地端不新增面向公网的测速用户入站。
- [ ] 2.5 若 Agent 本地探针无法在本版本完成，实施过渡方案时必须使用每条线路独立的短时凭据、最小有效期和显式撤销，并在代码注释、部署文档和风险记录中标明“仍属于公开入站认证面”；不得将过渡方案标记为最终修复。
- [ ] 2.6 更新 `LineSpeedtestService`，移除对固定凭据的直接依赖，改为调用受控探针服务或读取明确作用域的临时凭据；测速失败不得打印完整凭据或把凭据写入生成订阅。
- [ ] 2.7 增加回归测试：公开入站不含测速用户；测速成功仍能返回延迟/失败状态；超时和取消会清理临时资源；重复测速不会累积用户或监听端口。

### 里程碑 3：隔离并轮换协议代理中继凭据

- [ ] 3.1 删除 `INTERNAL_RELAY_TRANSIT_EMAIL`、`INTERNAL_RELAY_TRANSIT_UUID`、`INTERNAL_RELAY_TRANSIT_SECRET` 等源码固定值，以及 `internalRelayTransitUser()` 的全局静态返回值。
- [ ] 3.2 修改 `buildProtocolRelayOutbound()`：根据当前 relay line ID 获取对应 `RELAY_TRANSIT` 凭据；VLESS/VMess/TUIC 使用对应 UUID，Trojan/Hysteria2/Naive 使用对应密码/用户名，ShadowSocks 多用户模式沿用协议已有安全组装逻辑但不得回退到全局常量。
- [ ] 3.3 修改落地入站构建：`PROTOCOL_PROXY` 只接受当前中继线路的 transit 凭据，并确保同一节点上的其他线路凭据不能认证该入站。
- [ ] 3.4 增加线路级轮换动作：轮换时先生成新版本，原子更新入口与落地配置，确认两侧 Agent 回执成功后撤销旧版本；任一侧失败时保持旧版本并告警，不同时接受新旧两套长期凭据。
- [ ] 3.5 增加跨线路隔离测试：线路 A 凭据不能访问线路 B 的落地端；旧凭据在轮换后被拒绝；中继入口与落地配置版本不一致时线路状态不会误报为可用。
- [ ] 3.6 约束落地监听边界：优先使用节点私网/隧道地址或受控接口；若部署必须监听公网，必须在部署配置中要求 TLS/协议层认证、来源限制和最小开放端口，并在应用层保留按线路随机凭据。不能只依赖“管理员会配置防火墙”的说明。
- [ ] 3.7 为 landing port 增加可观测但脱敏的拒绝计数和线路 ID 维度告警，禁止记录 UUID、密码、完整连接 URL 或客户端提供的敏感认证值。

## 发布、回滚与运维注意事项

- **发布前**：备份 SQLite 主库及 `-wal`、`-shm` 文件，确认 Master 加密密钥可用且未变更；盘点所有 ACTIVE 线路和在线 Agent。
- **发布顺序**：先迁移并部署 Master，再初始化/轮换线路凭据，按入口/落地节点成对下发配置，收到双方成功回执后恢复线路；不允许只更新一侧。
- **旧配置处理**：所有含固定凭据的旧 Agent 配置必须在发布窗口内重载或删除；发布后检查配置快照和日志，确认旧常量未继续出现。
- **回滚**：优先回滚到仍支持受保护凭据的上一版本并恢复数据库备份；禁止为了快速恢复流量重新启用源码固定凭据。若只能恢复旧二进制，必须先通过防火墙临时隔离受影响落地端口，并建立明确的阻断告警和最短恢复期限。
- **应急轮换**：发现凭据泄露时按线路撤销并重新生成，不得只重启 Agent；若影响范围不明，按全部中继线路批量轮换处理。
- **归档**：全部任务和验收记录完成后执行 `pnpm plan:archive security-audit-public-relay-credentials.md`，由脚本刷新 `docs/plans/README.md`；未完成项不得归档。
